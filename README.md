# Claw Vault

Claw Vault is a Rust MCP server for Clawup agent wallets backed by Privy.

It exposes a constrained set of agent-facing wallet tools instead of the full Privy admin surface. Wallet creation requires a policy, transactions are validated before calling Privy, and agent-to-wallet bindings are stored locally by default.

## Tools

- `create_agent_wallet`
- `get_agent_wallet`
- `list_agent_wallets`
- `get_agent_wallet_balance`
- `send_agent_transaction`
- `sign_agent_message`
- `get_agent_transaction`

## Configuration

Required:

```sh
export PRIVY_APP_ID=...
export PRIVY_APP_SECRET=...
```

Optional:

```sh
export PRIVY_API_BASE_URL=https://api.privy.io/v1
export VAULT_WALLET_STORE=./data/agent-wallets.json
export VAULT_ALLOWED_CAIP2=eip155:8453,eip155:11155111
export VAULT_DEFAULT_MAX_WEI=50000000000000000
export VAULT_TRANSPORT=stdio
export VAULT_HTTP_BIND=0.0.0.0:8080
export VAULT_MCP_API_KEY=change-me
```

## Local stdio

```sh
cargo run --release
```


## Local HTTP Debugging

Start the HTTP MCP server locally:

```sh
export PRIVY_APP_ID=...
export PRIVY_APP_SECRET=...
export VAULT_TRANSPORT=http
export VAULT_HTTP_BIND=127.0.0.1:8080
export VAULT_MCP_API_KEY=dev-secret
cargo run
```

List MCP tools:

```sh
curl \
  -H 'x-api-key: dev-secret' \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}' \
  http://127.0.0.1:8080/mcp
```

Create an agent wallet with a default policy:

```sh
curl \
  -H 'x-api-key: dev-secret' \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {
      "name": "create_agent_wallet",
      "arguments": {
        "agent_id": "agent-demo-001",
        "chain_type": "ethereum",
        "caip2": "eip155:8453",
        "max_wei_per_transaction": "50000000000000000"
      }
    }
  }' \
  http://127.0.0.1:8080/mcp
```

This creates a Privy policy first, then creates a Privy wallet bound to that policy. The local binding is stored in `data/agent-wallets.json` unless `VAULT_WALLET_STORE` is set.

Create an agent wallet with an existing Privy policy:

```sh
curl \
  -H 'x-api-key: dev-secret' \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {
      "name": "create_agent_wallet",
      "arguments": {
        "agent_id": "agent-demo-002",
        "chain_type": "ethereum",
        "policy_id": "your_privy_policy_id"
      }
    }
  }' \
  http://127.0.0.1:8080/mcp
```

Fetch an agent wallet binding:

```sh
curl \
  -H 'x-api-key: dev-secret' \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/call",
    "params": {
      "name": "get_agent_wallet",
      "arguments": {
        "agent_id": "agent-demo-001"
      }
    }
  }' \
  http://127.0.0.1:8080/mcp
```

## HTTP Deployment for ClawUp

ClawUp requires a public HTTPS MCP endpoint with `http` or `sse` transport. For this server, deploy the HTTP transport and submit the public `/mcp` URL.

### 1. Generate the MCP API key

`VAULT_MCP_API_KEY` is generated by you. It is not a Privy key.

```sh
openssl rand -hex 32
```

Use the generated value both in this service and in the ClawUp MCP submission auth field.

### 2. Build the server

```sh
cargo build --release
```

The binary will be at:

```text
target/release/claw-vault
```

### 3. Start HTTP mode

```sh
export PRIVY_APP_ID=...
export PRIVY_APP_SECRET=...
export VAULT_TRANSPORT=http
export VAULT_HTTP_BIND=127.0.0.1:8080
export VAULT_MCP_API_KEY=<generated-api-key>
export VAULT_ALLOWED_CAIP2=eip155:8453,eip155:11155111
./target/release/claw-vault
```

Use `127.0.0.1:8080` when a reverse proxy terminates TLS on the same host. Use `0.0.0.0:8080` only when the service must listen on the network interface directly.

### 4. Put it behind HTTPS

Example Nginx reverse proxy:

```nginx
server {
    listen 443 ssl;
    server_name wallet.example.com;

    ssl_certificate /etc/letsencrypt/live/wallet.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/wallet.example.com/privkey.pem;

    location /health {
        proxy_pass http://127.0.0.1:8080/health;
    }

    location /mcp {
        proxy_pass http://127.0.0.1:8080/mcp;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

### 5. Verify the endpoint

Health check:

```sh
curl https://wallet.example.com/health
```

Unauthorized MCP requests should return `401` when `VAULT_MCP_API_KEY` is set:

```sh
curl -i https://wallet.example.com/mcp
```

Authorized MCP tool listing:

```sh
curl \
  -H 'x-api-key: <generated-api-key>' \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}' \
  https://wallet.example.com/mcp
```

`Authorization: Bearer <generated-api-key>` is also accepted.

### 6. Submit to ClawUp

In ClawUp Dashboard, submit the MCP tool with:

```text
Name: Claw Vault
Endpoint URL: https://wallet.example.com/mcp
Transport: http
Auth: api_key
API key: <generated-api-key>
```

Do not submit `PRIVY_APP_SECRET` to ClawUp. Privy credentials stay only in this server's deployment environment.

## Notes

This first implementation uses Privy REST calls directly. That keeps the Privy boundary small and stable for MCP submission. The client module can be replaced with `privy-rs` generated types later without changing the tool contract.
